# Работа с jwx-framework

Проект — универсальная основа для приложений: Vue Options API на клиенте,
Fastify, Prisma 7 и строгий TypeScript на сервере. Домены демонстраций показывают
возможности архитектуры; их роли, бизнес-правила и данные не становятся общими требованиями.

Перед изменениями прочитай подходящую документацию:

- [README](README.md) — запуск, структура и проверки.
- [Архитектура](docs/architecture.md) — DI, домены, нейминг и читаемый бизнес-слой.
- [Генератор доменов](docs/generator.md) — Prisma как источник DTO и HTTP-схем.
- [Клиент](docs/frontend.md) — Options API, структура компонентов, SCSS и адаптивность.
- [Авторизация](docs/authentication.md) — JWT, cookie, сессии и создание пользователя.
- [Пример Vodogon](docs/examples/vodogon.md) — особенности предметных демонстраций.
- [Песочница моделей](sandbox/water-billing/README.md) — изолированные реализации, PostgreSQL-проверки и измерение стоимости; [расширенные результаты](sandbox/water-billing/series-2/reports/REPORT.md).

## Разделение проекта

- `client` содержит Vue-приложение; его правила находятся в [client/AGENTS.md](client/AGENTS.md).
- `server` содержит backend; его правила находятся в [server/AGENTS.md](server/AGENTS.md).
- Общие Dockerfile, Compose, настройки окружения, документация и команды запуска находятся в корне.
- У клиента и сервера отдельные `package.json` и lock-файлы. Не перемещай их runtime-зависимости в root.
- Backend-домены находятся непосредственно в `server/src` и сохраняют плоские файлы.
  `framework`, `plugins`, `middlewares`, `generated` расположены рядом с `src` внутри `server`.

## Основные соглашения

- DI сервера явный и типизированный: сервис получает свой репозиторий через контракт
  и публичные API нужных доменов. Контроллеры не получают репозитории.
- Междоменные импорты проходят только через `*Types.ts`. Prisma и Fastify не попадают в чистые правила.
- `*Rules.ts` показывает понятные предметные действия. Форматирование, сортировку и большие
  объекты результата выноси в именованные помощники, сохраняя видимыми существенные решения.
- Генерируемые DTO и схемы берутся из Prisma. Не меняй защищённые `framework:generated` блоки
  или их хеши; меняй модель, конфигурацию или шаблон и запускай `npm run db:generate`.
- Клиентские компоненты используют Options API и строгий TypeScript. SCSS вложен в корневой
  селектор компонента; responsive-миксин располагается внутри селектора изменяемого элемента.
- Используй минимальную семантическую разметку и общие стили контролов. Не добавляй обёртки,
  utility-фреймворк, динамический DI или глобальные модификации прототипов ради удобства.
- JWT остаётся в HttpOnly cookie. Не добавляй токены в localStorage, пароли по умолчанию
  и тестовый обход аутентификации. Секреты и пользовательские данные не входят в Git.

## Проверки и данные

- `npm run check` проверяет обе части; `check:server` и `check:client` доступны отдельно.
- Для затронутого поведения добавляй и запускай подходящие проверки, включая HTTP и браузерные сценарии.
  Документационные правки требуют сверки фактов и ссылок.
- PostgreSQL-интеграции запускаются с отдельной БД через `TEST_DATABASE_URL`; без неё пропускаются.
- Не сбрасывай рабочие данные ради тестов, seed или переустройства папок. Миграции сохраняй в Git.
- Не публикуй `.env`, cookies, пароли, дампы, generated Prisma Client, node_modules или результаты сборки.
- В `sandbox/water-billing` сохраняй исходные результаты эксперимента: frozen-файлы нельзя
  править под ответы кандидатов. Новые проверки и исправления описывай отдельной фазой.
  Workspace, авторизация и сырые логи моделей остаются в игнорируемой `.local/llm-benchmark`.
- Поддерживай документацию вместе с кодом. Отделяй работающие возможности от будущих планов;
  полный перенос демонстрационного приложения не является задачей универсального ядра.
