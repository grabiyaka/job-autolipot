# Фаза 3: Telegram, расписание и подача откликов

Этапы 1 «Сбор» и 2 «Отбор» работают: `npm run collect`, `npm run score`, `npm run cycle`
([guide.md](../guide.md)). Фаза 3 закрывает остаток дорожной карты: подачу откликов через
DeepSeek, управление из Telegram и расписание. В старой дорожной карте это этапы 3, 4 и 5.

Это **план**, кода фазы 3 пока нет. Здесь записаны все решения, результаты живой пробы и задание
по каждому пакету, чтобы работу можно было продолжить с чистым контекстом.

## Цель фазы

```
                 ┌──────────── Telegram-бот (управление и отчёты) ────────────┐
                 │  /run collect|score|cycle|apply   /schedule   /on /off     │
                 │  отчёты после прогона, вопросы агента, ✅ отправить         │
                 └───────┬───────────────────────────────────────┬──────────┘
                         │ планировщик (cron в базе)              │ ответы → банк
                         ▼                                        ▼
LinkedIn ─► collect ─► score (qwen) ─► Job-Tracker To Apply ─► apply (DeepSeek + Playwright MCP)
                                                                  │
                         стоп перед Submit ◄──────────────────────┤
                         ты проверяешь → ✅ → Submit → applied ──► JT: Application APPLIED
```

## Порядок работ

| № | Пакет | Что даёт | Зависит от | Статус |
|---|---|---|---|---|
| А | [Банк ответов](a-answers.md) — домен `src/answers` | типовые ответы на вопросы форм: годы опыта, email, согласия, правила по зарплате | — | ⏳ |
| Б | [Telegram-бот и расписание](b-telegram.md) | бот управляет сбором и оценкой: запуск вручную, cron, вкл/выкл, отчёты | А (команда `/answers`) | ⏳ |
| В | [Запуск агента и защита](c-agent-runner.md) — `plugins/claude-agent.ts` | безопасный запуск `claude -p` на DeepSeek, хук «не отправлять», блокировка браузера, учёт стоимости | — | ⏳ |
| Г | [Подача — домен `src/applications`](d-applications.md) | `npm run apply`, стоп перед Submit, `--submit`, вопросы → `needs_input`, автоподача в боте | А, В, Д | ⏳ |
| Д | [Эндпоинт в Job-Tracker](e-job-tracker.md) (другой репозиторий) | агент может отметить вакансию поданной | — | ⏳ |

Порядок по твоему решению: **А → Б**, потом подача (**В** и **Д** можно параллельно, **Г** — последним),
и в конце в бот добавляется автоподача. В и Д не зависят от А и Б, их можно начать раньше
в отдельных сессиях.

Фаза закрыта, когда:

- из Telegram можно запустить сбор, оценку и подачу, включить и выключить расписание;
- 5 реальных вакансий LinkedIn Easy Apply заполнены правильно и остановлены перед Submit,
  одобренные отправлены, в JT они стали Application со статусом APPLIED;
- вопросы агента приходят в Telegram, ответ сохраняется в банк, и подача продолжается.

## Как продолжить с чистым контекстом

1. Прочитать этот файл и [decisions.md](decisions.md).
2. Отметить статус в таблице выше: ⏳ не начат, 🔧 в работе, ✅ готов.
3. Взять следующий пакет по порядку, прочитать его файл и правила [server/AGENTS.md](../../server/AGENTS.md).
4. Перед кодом показать пользователю короткий план и вопросы из раздела «Открытые вопросы» пакета.
5. После пакета: `npm run check`, обновить документацию (guide, overview, этот файл), без коммита
   до просьбы пользователя.

## Открытые вопросы (общие)

1. **Telegram-бот:** нужен новый бот от @BotFather (токен в `.env` как `TELEGRAM_BOT_TOKEN`) и твой chat id.
   Работающий `agent-tg-bot` (local-agent) не трогаем — см. [b-telegram.md](b-telegram.md#почему-отдельный-бот).
2. **Email в LinkedIn:** добавить `illia.herasymets@gmail.com` в аккаунт LinkedIn
   (Settings → Sign in & security → Email addresses), иначе агент не сможет выбрать его в форме.
3. **Скриншоты:** Playwright MCP пишет их в `/var/lib/agent-playwright-mcp/output`, закрытую для
   пользователя `elijah`. Для скриншотов в Telegram нужна общая папка (правка юнита, `sudo` — делаешь сам).
