# Сервер универсального фреймворка

Цель проекта — универсальная основа для backend-приложений на Fastify, Prisma 7 и TypeScript.
Домены текущей демонстрации служат примерами использования. Их бизнес-правила, роли и модель
данных не определяют архитектуру всех будущих приложений.

Перед изменением архитектуры или добавлением домена прочитай
[соглашения проекта](../docs/architecture.md). [README](../README.md) описывает состояние проекта,
запуск и проверки. Особенности демонстраций документируются отдельно в `../docs/examples`.
Для генерируемых доменов прочитай [руководство генератора](../docs/generator.md).

Все пути ниже относительны каталогу `server`. Серверные команды выполняй из него
либо используй `npm --prefix server run …` из корня. Общие правила — в [корневом AGENTS.md](../AGENTS.md).
Авторизация описана в [руководстве JWT](../docs/authentication.md).

## Структура и нейминг

- `src` содержит только домены непосредственно в корне; например, `users`, `tasks`, `interviews`.
- Внутри домена сохраняй плоскую структуру. Не добавляй обязательные подпапки слоёв и пустые файлы по шаблону.
- Доменные папки — английское множественное число; файлы — PascalCase с единственным числом:
  `TaskService.ts`, `TaskRules.ts`. Основной класс совпадает с именем файла.
- Публичная граница — `*Types.ts`, включая интерфейс `*Api`. Внутренние порты — `*Contracts.ts`.
- Маршруты и их JSON-схемы хранятся вместе в доменном `*Routes.ts`.
- `framework`, `plugins`, `middlewares`, `generated` остаются вне `src`.
  Prisma Client генерируется по схеме приложения; используй `npm run db:generate`, не редактируй результат.
- Конкретная сборка в `framework/composition` принадлежит приложению. Общую основу не связывай
  с названиями его доменов, ролями или предметными единицами измерения.

## Зависимости и бизнес-логика

- Используй явный DI через типизированные конструкторы. Конкретные реализации связывает composition;
  глобальный локатор, строковый контейнер и динамическое присваивание зависимостей не нужны.
- Между доменами импортируй только публичные `*Types.ts`. Нужный чужой сервис получай через его API-интерфейс.
- Сервис использует собственный репозиторий через контракт. Чужие репозитории недоступны.
  Контроллер не получает никакие репозитории или их внутренние контракты.
- Сохраняй автокомплит и строгую типизацию; не скрывай отсутствующие зависимости с помощью `any` или cast.
- `*Rules.ts` показывает понятные предметные шаги. Преобразования, подробные вычисления,
  сортировку и большие объекты результата выноси в именованные чистые помощники.
  Значимые решения и порядок действий должны оставаться видимыми в сценарии.
- Помощники могут реализовывать проверки и расчёты. `*CalculationData.ts` — возможная роль для расчёта,
  а не обязательный файл каждого домена. `*Mapper.ts` считается инфраструктурой.
- Правила и предметные помощники не выполняют I/O и не зависят от Fastify/Prisma.
  Время и ID передавай явно, когда они нужны; не храни текущего актора или запрос в общем сервисе.
- Плагины содержат недоменные технические возможности, middleware — идентификацию и HTTP-доступ.
  Роли определяет приложение; предметные проверки доступа выполняются также в сервисе/правилах.
- Уровни HTTP-доступа импортируются из отдельных `middlewares/*Access.ts` и явно подключаются
  через `preHandler` в доменном `*Routes.ts`. Используй `publicAccess`, `authenticatedAccess`,
  `guestAccess`, `generalAccess`, `adminAccess` или типизированный `rolesAccess(...roles)`.
  Последний использует точный список ролей; не добавляй скрытое наследование прав.
- В текущем приложении `guestAccess` допускает admin/manager/guest, `generalAccess` — admin/manager,
  `adminAccess` — admin. `authenticatedAccess` также допускает foreign; это пользователь без
  рабочего доступа, а не анонимный посетитель. Проверки сервиса используют Actor и чистые
  `requireRole` / `hasGeneralAccess`; доступ к конкретным данным проверяется отдельно.
- Если необходима атомарная запись в нескольких доменах, используй UoW и узкие публичные
  контракты участников. Не открывай чужой репозиторий ради общей транзакции.
- Версии, идемпотентность, аудит, события, снимки и неизменяемая история выбираются под задачу.
  Не делай их обязательными для каждого домена на основании конкретного примера.
- Модель CRUD, правила изменения и удаления, единицы измерения и форматы данных принадлежат
  приложению. Сохраняй существующее поведение домена при общих изменениях фреймворка.

## Проверки и документация

- Источник типов генерируемого CRUD — Prisma-модель; `prisma/domains.json` выбирает поля и операции.
  Не дублируй типы полей в конфигурации. `npm run db:generate` обновляет Prisma Client и домены.
- Не редактируй защищённые блоки `framework:generated` и их хеши вручную.
  Меняй модель, конфигурацию или шаблоны `framework/generator`, затем запускай `domain:generate`.
  Собственные методы, API и маршруты добавляй вне блоков; эти секции сохраняются.
- `npm run domain:check` входит в `npm run check`; устаревшие блоки и конфликты должны быть исправлены.
  Удаление домена и его подключения выполняется явно: генератор не удаляет исходники.
- Новый CRUD подключай через composition с явной policy и функцией контекста.
  Policy операции не заменяет проверку владения записью или фильтрацию по организации.
- HTTP middleware CRUD задавай в ручной секции `*Routes.ts` четвёртым аргументом
  `register*CrudRoutes`: типизированный `*RouteAccess` сопоставляет операции и preHandler.
  Не меняй для этого сгенерированный блок и не встраивай роли приложения в шаблон генератора.
- `framework/generator` — инструмент разработки. Runtime-модули не импортируют его;
  готовые домены сохраняют общие ограничения Prisma, DI и междоменных импортов.
- `npm run architecture` проверяет границы импортов, включая алиасы и реэкспорты.
  Не ослабляй проверку ради обхода границ. Имена, циклы DI и читаемость также требуют ревью.
- Для изменений поведения используй `npm run check` и подходящие интеграционные проверки.
  PostgreSQL-тесты требуют отдельной БД через `TEST_DATABASE_URL`; без неё они пропускаются.
- Не сбрасывай данные работающего приложения ради тестов и seed.
- Общие соглашения фиксируй в `../docs/architecture.md`, состояние проекта и запуск — в README,
  особенности приложений — в `../docs/examples`. Для документационных правок проверь факты и ссылки.
- Отличай универсальную цель от текущего состояния прототипа. Не описывай ещё не выделенные
  механизмы как готовое переиспользуемое ядро и не считай полный перенос приложения задачей фреймворка.

## Аутентификация

- Используй реального пользователя и сохранённую JWT-сессию; не возвращай статические demo-токены.
- JWT хранится в HttpOnly cookie; транспортные подробности остаются в middleware и HTTP-адаптерах.
- Сервис получает обычный Actor, а текущие права берутся из действующей записи пользователя.
- Не добавляй пароли по умолчанию, публичную регистрацию или обход аутентификации для тестов.
- Проверяй Origin и обязательный заголовок для изменяющих запросов с cookie.
- Пользователей создаёт интерактивная команда `user:create`; не сохраняй пароли в исходниках или CLI-аргументах.
- CLI по умолчанию создаёт manager; admin требует явного `--role admin`. Prisma по умолчанию
  сохраняет foreign. Только guest может иметь необязательную связь `subscriberId` для демонстрации.
- Миграции ролей сохраняют пользователей и сессии. Исторические operator/subscriber допустимы
  только в неизменяемых снимках; не переписывай историю и не принимай эти роли при новом входе.
